# نشر NAQAA Field Lab API على FastAPI Cloud

هذه الخطوات مخصصة للمشروع `field-lab/api` فقط، ولا تغيّر إعدادات Cloudflare أو Render أو Railway.

## 1. إنشاء خدمة API
1. افتح https://fastapicloud.com/ وسجّل الدخول.
2. اختر إنشاء تطبيق من GitHub واربط مستودع `naqaaholding-create/Naqaa-HOLDING-`.
3. اضبط **Root Directory / Application Directory** على `field-lab/api`.
4. أنشئ التطبيق وانتظر اكتمال البناء. ملف الدخول هو `main.py` وفيه كائن FastAPI باسم `app`.
5. بعد النشر، اختبر `https://<عنوان-الخدمة>/health` و`/docs`. لا تعتبر الخدمة ناجحة قبل أن يعيد `/health` حالة `ok`.

## 2. قاعدة البيانات والإعدادات
استخدم PostgreSQL دائمًا من مزوّد قاعدة بيانات موثوق، مثل خطة Neon المجانية، ثم أضف المتغيرات في إعدادات الخدمة السرية:
- `FIELD_LAB_ENV=production`
- `FIELD_LAB_JWT_SECRET`: سر عشوائي قوي لا يقل عن 32 بايت؛ أنشئه داخل مدير الأسرار ولا تضعه في Git أو الدردشة.
- `FIELD_LAB_DATABASE_URL`: رابط PostgreSQL الخاص بالخدمة، مع SSL كما يطلب المزوّد.
- `FIELD_LAB_ALLOWED_ORIGINS`: عنوان HTTPS الدقيق للواجهة بعد التأكد من عنوانها.
- `FIELD_LAB_LIVE_PAYMENTS_ENABLED=0`

لا تستخدم SQLite في الخدمة المنشورة؛ بياناتها قد تضيع عند إعادة التشغيل أو تغيير النسخة. لا تفعّل المدفوعات الحقيقية أثناء الاختبار.

## 3. ربط الواجهة
بعد معرفة عنوان API الحقيقي، حدّث `field-lab/api-config.js` ليشير إلى عنوان HTTPS هذا، ثم انشر الواجهة من جديد. يجب أن يطابق `FIELD_LAB_ALLOWED_ORIGINS` عنوان الواجهة بالضبط.

## 4. فحوصات القبول
- `GET /health` يعيد `status: ok`.
- `GET /payments/status` يعيد `payments_enabled: false` أثناء الاختبار.
- إنشاء حساب تجريبي وتسجيل الدخول بنجاح.
- حفظ موقع تجريبي ثم قراءته بعد إعادة تحميل الصفحة وإعادة تشغيل الخدمة.
- التحقق من أن البيانات تبقى موجودة في PostgreSQL.

## تنبيه
هذا الملف لا يعني أن الخدمة نُشرت بالفعل. لا يوجد عنوان إنتاجي حتى الآن؛ يجب الحصول عليه من لوحة الاستضافة بعد إنشاء التطبيق. لا ترسل كلمات المرور أو مفاتيح الأسرار أو مفاتيح المحافظ في المحادثة.
